# 从一局灭灯游戏，到一段高中就能懂的数学

> 本文献给所有"卡在灭灯游戏里、怀疑人生"的玩家。
> 你会看到：一个看似靠运气的小游戏，背后其实是一道高中水平的方程题；
> 而"有没有解、怎么解"这个问题，曾经让数学家们认真研究了三十多年。
> 全文只用高中数学（甚至不到高中），配手算示例，零基础可懂。

---

## 开篇：那一格，怎么都灭不掉

你大概玩过这类游戏：一张方格棋盘，有些格子亮着灯。你点一下某个格子，它自己会灭（或亮），同时它上下左右四个邻居也跟着翻转。目标很单纯——**把所有灯都按灭**。

一开始你很有信心，东点西点，灯越来越少。可总在最后剩一两格，怎么点都不对：点 A，B 又亮了；点 B，A 又回来了。像两个调皮的孩子，你按下这个，那个就跳起来。

于是你开始想一个问题，一个很朴素、却很深刻的问题：

> **这局，到底有没有解？还是我纯粹在跟运气较劲？**

如果真有解，又**怎么算出来**，而不是靠瞎试？

这篇文章，就从这个疑惑出发，一路走到数学的核心。你会发现，答案不在运气里，而在一套漂亮得令人意外的算术中。

---

## 一、先摸门道：两个反直觉的小技巧

在搬出数学之前，先送你两把"游戏内"的钥匙。它们听起来理所当然，却悄悄改变了问题的性质。

**技巧 1：同一个格子按两次，等于没按。**
灯只有两种状态，亮↔灭，按一下翻转，再按一下翻回来。所以"按两下"和"不按"完全一样。推论：**每个格子，你最多只需要按一次**（按多了纯属浪费）。

**技巧 2：按的顺序，无所谓。**
你先按 A 再按 B，和先按 B 再按 A，结果是一样的——因为每次翻转都是独立作用在灯上，互不干扰（数学上叫"可交换"）。

这两点合起来，发生了一件大事：

> 原来"怎么按"不是一个**时间序列**（先按谁后按谁），而只是一个**集合**——**哪些格子需要被按一次**。

问题瞬间从"编排一套动作"变成"挑出一组格子"。这一步看似平常，却是通往数学的门槛：一旦变成"选集合"，我们就可以用数字和方程来描述了。

## 二、好奇心上线：到底有没有解？

带着"选集合"的思路再玩，你会更挫败，也会更好奇。

有时候你明明觉得就差一点，却怎么都凑不出来；有时候你换一组格子试，灯反而更乱。这时候那个问题变得更尖锐：

> 这不是我笨不笨的问题，而是这盘灯**在数学上到底存不存在一个解法**？

要回答它，我们需要一种语言，把"棋盘长什么样""按某个格子会发生什么""最后要变成什么样"全部翻译成数字，然后让数字自己告诉我们答案。

下面，请出这套语言。放心，它比你想的简单。

## 三、数学登场（只用高中知识）

### 3.1 用 0 和 1 记状态 —— 什么是"向量"

先把灯翻译成数字：**灭 = 0，亮 = 1**。

这样，整个棋盘就不再是一堆灯，而是一长串 0 和 1。比如一个 3×3 的棋盘，某一刻长这样（● 代表亮，· 代表灭）：

```
· ● ·
● · ●
· ● ·
```

把它按行排成一串，就是：

```
0, 1, 0,  1, 0, 1,  0, 1, 0
```

这一串有序的数字，在数学里有个名字叫**向量**（vector）。别被词吓到——向量就是"一串按顺序排列的数"，跟你用 (x, y) 表示平面上的一个点是一回事，只不过这里更长。

**所以，"棋盘的状态"= 一个向量。** 一句话就讲完了。

### 3.2 一种"怪加法" —— GF(2)

接下来是关键一步，也是全文最妙的地方。

当你按下一个格子，有些灯翻转了。对某一盏具体的灯来说，它被翻转了**几次**？

- 被翻了**偶数次**（0 次、2 次、4 次……）→ 等于没翻，状态不变；
- 被翻了**奇数次**（1 次、3 次……）→ 状态翻转。

注意到了吗？我们根本不关心"翻了 3 次还是 5 次"，只在乎**奇数还是偶数**。这种"只论奇偶"的世界里，加法变成了一种奇怪但极其简洁的规则：

```
0 + 0 = 0      （没翻 + 没翻 = 没翻）
1 + 0 = 1      （翻了 + 没翻 = 翻了）
0 + 1 = 1      （没翻 + 翻了 = 翻了）
1 + 1 = 0      （翻了 + 翻了 = 没翻！）
```

最后这条 `1 + 1 = 0` 是灵魂：翻两次等于没翻。这种"加法"在数学上就叫**模 2 加法**，也被叫做**异或（XOR）**——两个一样就归零，两个不一样才是一。

数学家伽罗瓦（Galois）早就系统研究过"只有 0 和 1 两种元素、加法按上面规则、乘法照常"的算术系统，给它起了个学名：**GF(2)**（Galois Field with 2 elements，二元域）。

> 你完全不用记住这个名字。你只需要记住一句话：**GF(2) 就是"只关心奇偶的算术"，1+1=0。**

它一点都不抽象，生活里到处是它：
- 电灯开关：拨上去再拨下来，回到原样；
- 投票：一正一反抵消；
- 翻硬币：翻两次回到正面。

灭灯游戏，不过是这套"奇偶算术"的一场大型实景演出。

### 3.3 每个按钮，都是一张"图纸"

现在看"按下一个格子"这件事。

按下格子 k，它会翻转"自己 + 上下左右邻居"。这是一组**固定的**格子。我们把这组格子也写成 0/1 图：要翻的地方写 1，不翻写 0。这就是按钮 k 的**按压图案**（press pattern），也就是它专属的一张"施工图纸"。

以 3×3 为例，按下正中央那格，会翻中央和上下左右共 5 格：

```
· · ·
· ● ·
· · ·
```
（● 表示"这张图纸会在这些位置翻转灯"）

按下左上角那格，会翻它自己和右边、下边共 3 格：

```
● ● ·
● · ·
· · ·
```

整张棋盘一共有 9 个按钮，也就有 9 张这样的图纸。

### 3.4 玩游戏 = 解一道方程

重头戏来了。我们要把"玩游戏"翻译成"解方程"。

设 `x₁, x₂, …, x₉` 表示"对应的 9 个按钮按不按"：按了就是 1，不按就是 0。这九个 0/1 凑在一起，就是另一个向量 **x**——它正是我们要求的"答案"（该按哪些格子）。

你按下的所有按钮，它们的"图纸"会叠加起来（叠加规则就是 3.2 的怪加法：某格被翻奇数次就变，偶数次就不变）。叠加的结果，必须**正好等于当前棋盘的亮灯图 b**——因为亮着的格要被翻奇数次才能灭，灭着的格要被翻偶数次才能保持灭。

把"所有图纸叠加 = 当前亮灯图"这件事写成矩阵形式，就是：

```
A · x = b      （所有运算都在 GF(2) 里，即 1+1=0）
```

其中：
- **A** 是把 9 张图纸并排排成的"大表格"（数学叫矩阵）；
- **x** 是"按不按每个按钮"（未知，待求）；
- **b** 是当前棋盘的亮灯图（已知）。

**看到了吗？灭灯游戏，等价于在 GF(2) 里解一个线性方程组。**

这正是高中数学里"二元一次方程组"的亲戚，只不过：① 未知数可能几十个；② 加减法换成"1+1=0"。本质上，一模一样。

于是那个折磨人的问题——"这局到底有没有解"——翻译成了教科书里的一句话：

> **方程组 A·x = b 在 GF(2) 上有没有解？**

## 四、高斯消元：手把手算一遍（2×2 完整演示）

怎么解 `A·x = b`？高中教过标准武器：**高斯消元**——一行一行地消去未知数，把方程组整理成"阶梯状"，再从下往上倒推。灭灯游戏用的还是这招，只是加减法换成异或（1+1=0）。

为了让你看清每一个动作，我们把棋盘**缩小到 2×2**（四盏灯），这样四步就能手算到底。原理和大棋盘完全相同，只是数字少。

把四盏灯编号为：

```
1  2
3  4
```

按下每个按钮，会翻"自己 + 正交邻居"，于是四张图纸是：

- 按 1：翻 1,2,3  →  `[1,1,1,0]`
- 按 2：翻 1,2,4  →  `[1,1,0,1]`
- 按 3：翻 1,3,4  →  `[1,0,1,1]`
- 按 4：翻 2,3,4  →  `[0,1,1,1]`

设 `x₁…x₄` 为按不按，那么"每盏灯被翻的总次数（mod 2）等于它当前是否亮"，得到方程组（所有等号都按 1+1=0 来算）：

```
(1)  x₁ + x₂ + x₃        = b₁
(2)  x₁ + x₂        + x₄ = b₂
(3)  x₁        + x₃ + x₄ = b₃
(4)       x₂ + x₃ + x₄ = b₄
```

**举个具体例子**：假设只有 1 号灯亮，其余灭，即 `b = [1, 0, 0, 0]`。我们来求 x。

消元开始（记住：1+1=0）：

- 由 (1) 得：`x₁ = 1 + x₂ + x₃`（把右边的 x₂、x₃ 移到左边变号，但 GF(2) 里"减"就是"加"）。
- 代入 (2)：`(1+x₂+x₃) + x₂ + x₄ = 0` → `1 + (x₂+x₂) + x₃ + x₄ = 0` → `1 + 0 + x₃ + x₄ = 0` → `x₃ = 1 + x₄`。
- 代入 (3)：`(1+x₂+x₃) + x₃ + x₄ = 0` → `1 + x₂ + (x₃+x₃) + x₄ = 0` → `1 + x₂ + x₄ = 0` → `x₂ = 1 + x₄`。
- 代入 (4)：`x₂ + x₃ + x₄ = 0` → `(1+x₄) + (1+x₄) + x₄ = 0` → `(1+1) + (x₄+x₄) + x₄ = 0` → `0 + 0 + x₄ = 0` → **`x₄ = 0`**。

倒推回去：

- `x₄ = 0`
- `x₃ = 1 + 0 = 1`
- `x₂ = 1 + 0 = 1`
- `x₁ = 1 + x₂ + x₃ = 1 + 1 + 1 = 1`（因为 1+1=0，0+1=1）

所以解是 **x = [1, 1, 1, 0]**，也就是：**按 1、2、3 号，不按 4 号**，就能把"只有 1 号亮"的局面灭掉。

验证一下：按 1、2、3 后——
- 灯 1 被按钮 1、2、3 翻（都翻它）→ 3 次（奇数）→ 亮变灭 ✓
- 灯 2 被按钮 1、2 翻 → 2 次（偶数）→ 保持灭 ✓
- 灯 3 被按钮 1、3 翻 → 2 次（偶数）→ 保持灭 ✓
- 灯 4 被按钮 2、3 翻 → 2 次（偶数）→ 保持灭 ✓

全部熄灭。成了。

> **重点不是这个答案，而是这个过程**：我们用纯机械的步骤，从"四个方程"推出了"该按哪几格"。大棋盘（比如 8×8 有 64 个未知数）也是同一套动作，只是数字多——电脑用"位运算"能在几毫秒里算完。我们写的灭灯游戏求解器，干的就是这件事。

顺带一句：如果在消元过程中，出现"0 = 1"这种矛盾（比如某行左边全消没了，右边却是个 1），就说明**无解**——这正是下一节要聊的诡异现象。

## 五、诡异的"安静模式"：为什么有的局永远灭不了

高斯消元偶尔会撞上一个怪事：算着算着，出现矛盾，告诉我们"这局没解"。

为什么会这样？答案藏在一种奇妙的东西里，叫**安静模式（quiet pattern）**。

### 5.1 什么是安静模式

设想存在这样一组按钮：你把它们全按一遍，**灯居然一点都没变**——每一盏灯都被翻了偶数次（偶数次翻转 = 没翻）。

这种"按了等于白按"的按钮组合，就叫安静模式。它像是游戏里的一个"幽灵操作"：你费劲按了一通，世界毫无波澜。

以经典的 5×5 为例（商业版灭灯游戏就是 5×5）。下面这张图是一组真实的安静模式——● 表示"按这个格"，· 表示"不按"：

```
· ● ● ● ·
● · ● · ●
● ● · ● ●
● · ● · ●
· ● ● ● ·
```

你若真把这 13 个格子按一遍，棋盘上每一盏灯都恰好被翻了偶数次，于是**整盘纹丝不动**。可以用手数任意一盏灯验证（比如正中央，它被自己和四个邻居中的若干按下所影响，总数是偶数）。这就是安静模式的本质：一组"相互抵消"的按压。

### 5.2 零空间（null space）

把所有安静模式收集到一起，构成了一个集合。在数学上，它恰好是方程

```
A · x = 0      （按了 x，结果灯全不变，即"零变化"）
```

的全部解。这个解的集合，叫矩阵 A 的**零空间（null space）**，也叫**核（kernel）**。

- 如果零空间里**只有**"全都不按"（x 全为 0），说明没有任何幽灵操作，游戏干干净净——**所有局面都能解**。
- 如果零空间里还藏着别的东西（非平凡的安静模式），说明有些亮灯图是"够不着"的——**无论你怎么按，都永远灭不了**。

### 5.3 不同棋盘，命运大不同

安静模式有多少个（自由度），直接决定了"随机一盘能赢的概率"。我们把前面手算和电脑验证的结论列成一张表：

| 棋盘 | 安静模式自由度 | 随机一盘可解比例 |
|------|------|------|
| 2×2、3×3、6×6、7×7、8×8、10×10、12×12、13×13、15×15 | 0 | **100%**（随便玩都能赢） |
| 5×5 | 2（共 4 个安静模式） | 1/4 = **25%** |
| 4×4 | 4（共 16 个安静模式） | 1/16 ≈ **6.25%** |
| 11×11 | 6 | 1/64 ≈ 1.56% |
| 9×9、16×16 | 8 | 1/256 ≈ 0.39% |
| 14×14 | 4 | 1/16 ≈ 6.25% |

看出门道了吗？**很多尺寸（如 4×4、5×5、9×9）是"奇异"的**——它们藏着安静模式，导致大量随机局面根本无解。其中 4×4 最夸张：随机撒点，只有约 **6.25%** 的盘能赢，十局九输。

这也揭开了一个小秘密：我们的灭灯游戏（网页版和安卓版）**不是纯随机撒亮灯**的。它先用高斯消元判断"这盘能不能解"，如果不能，就用安静模式做一点"奇偶性修正"，把它调成一个**保证有解**的局面再交给你。否则像 4×4 这种尺寸，你几乎每局都在跟不可能较劲。

> 所以，"这局到底有没有解"这个问题的完整答案分两层：
> **能不能判断？能，高斯消元或安静模式点积即可秒判。**
> **是不是总有解？不一定——取决于棋盘尺寸里藏着几个安静模式。**

## 六、数学本质与一段三十年的研究史

### 6.1 它到底是什么数学

剥开外壳，灭灯游戏是三件事的同一个内核：

1. **GF(2) 上的线性代数**——就是本文讲的：向量、矩阵、线性方程组，只是数字只有 0 和 1。
2. **图上的"开关游戏"（sigma-game / parity domination）**——把棋盘看成一个图（格子是点，正交相邻是边），按下顶点翻转"自己 + 邻居"。这类问题统称 *Lights Out on graphs*。
3. **切换网络 / 编码理论的近亲**——它的"安静模式"和线性码的"核"是同一个对象。

### 6.2 一段历史

- **1989 年**，数学家 Klaus Sutner 在《Linear Cellular Automata and the Garden-of-Eden》中，为"一般图上的开关游戏"奠定了理论基石：可解性完全由矩阵 `A = I + 邻接矩阵` 在 GF(2) 上是否可逆决定。
- **1995 年**，玩具公司 Tiger Toys 推出 5×5 商业版 *Lights Out*，风靡一时，也把这个问题正式送进大众视野，引发数学界系统研究。
- **Jaap Scherphuis** 写下了堪称权威的《The Mathematics of Lights Out》，逐一枚举了各尺寸棋盘的安静模式数量与具体图案，至今是爱好者必读。
- 随后一系列论文把研究推向深入：Goldwasser、Klostermeyer、Trapp 等人在《Characterizing Switch-Setting Problems》(2002) 中刻画了"哪些图上的开关问题可逆"；Klostermeyer 与 Schwartz 在《A Zoo of Lights Out!》里研究了"马步翻转""对角翻转""棋盘格翻转"等五花八门的变体；Golin 与 Ma (2003) 则用生成函数分析可解率与最少步数分布。

### 6.3 一个反差萌的彩蛋

你以为"能不能解"是难点？其实更难的是另一个问题：**在能保证有解的前提下，按最少的格子把它灭掉**。

这个"求最少按键数"的问题，在数学上属于 **NP-hard**（没有已知的快速通用算法能保证最优）。也就是说，就连这种看似简单的小游戏，在最优化层面也藏着计算复杂性的深坑。

这大概是灭灯游戏最迷人的反差：**判断有无解，高中水平足矣；求最快解法，却要撼动计算机科学的天花板。**

## 七、回到游戏：一点实用的话

聊完数学，回到屏幕前那张棋盘。你现在手里多了一件东西：

- 记住"**每个格最多按一次、顺序无关**"，思路会从"瞎试"变成"挑集合"；
- 明白"**卡住可能是因为这局本就没解**"（尤其 4×4、5×5 这类尺寸），就不必跟自己过不去了；
- 也知道"**有解时，最少按键未必容易**"——所以偶尔多按几步，很正常。

数学没有让你变成无敌玩家，但它把你从"运气"里打捞出来，告诉你哪些努力有意义、哪些只是与幽灵较劲。
